# TripPlan

Plan. Pack. Go.  
旅行の「計画・準備・実行」を、ひとつのUIにまとめる旅行計画アプリ。

---

## 企画背景（Why）

旅行の計画をするたびに、フライト・宿泊・食事・アクティビティなどの情報が
予約サイト／メモアプリ／スプレッドシートに分散し、
「どこに何を残したか」を思い出すだけでコストがかかっていました。

特にストレスだったのは次の3点です。

- **情報が散在して確認が面倒**（どのツールに何を書いたか分からなくなる）
- **総費用の把握が煩雑**（メモと予約画面を行き来して足し算する）
- **旅行中にスマホで素早く見返せない**（当日の行動判断が遅れる）

この「分散による確認ストレス」を減らし、
準備や旅行当日の意思決定をスムーズにすることを目的に開発しました。

---

## コンセプト（What）

TripPlan は、旅行計画に必要な **旅程・持ち物・メモ** を一元管理できる  
**モバイルファースト**な Web アプリケーションです。

個人旅行から少人数グループ旅行まで、
「情報が散らばる」「確認が面倒」といった課題を解消します。

---

## 体験設計の方針（How / UIで大事にしたこと）

旅行中に最も頻繁に見るのはスマホ画面なので、
**情報量を増やすより “探す回数を減らす（探索コストを下げる）”** ことを優先しました。

- **モバイルファースト**：小さな画面でも迷わない導線
- **クリーン＆モダン**：視覚的ノイズを減らして確認ストレスを下げる
- **カードUI**：情報をブロック化して視線誘導を明確にする
- 重要情報に **2タップ以内** で到達できることを意識

---

## 主な機能（MVP）と、選んだ理由

「旅行の準備〜当日までに本当に困るところ」から逆算して、MVPを絞りました。

### 認証
- ユーザー登録 / ログイン
- パスワードリセット（メール）
- ゲストログイン（ポートフォリオ閲覧用）

→ 個人データを扱う前提として、最低限のアカウント機能を先に確立

### マイ旅
- マイ旅一覧（すべて / 今後 / 過去）
- 旅の作成・編集・削除（確認ダイアログあり）

→ 旅行は複数同時に計画することがあるため「一覧性」と「見返しやすさ」を優先  
→ 誤操作による削除を防ぐため確認ダイアログを採用

### 旅詳細
- 旅程（Activities）
  - 日別表示
  - 自動ソート
- 持ち物リスト
  - 固定カテゴリ
  - チェック機能
- メモ（旅単位で1つ）

→ 旅行中の確認を想定し「日別で時系列に見える」ことを最重要に設計  
→ 出発前の準備を “考える” ではなく “チェックする” 体験に寄せるため持ち物リストを採用  
→ 予約番号・注意事項・URLなど散らばりがちな断片情報を「旅単位」に集約

## 開発プロセス（思考プロセスが伝わる進め方）

実装から入らず、先に「意思決定の根拠」を残すことを意識して進めました。

1. 企画書（原案）を手動で作成（課題・価値・MVP）
2. 原案をベースに AIでブラッシュアップ（読み手に伝わる構成へ整理）
3. 技術選定と設計方針（SSR中心など）を文章化
4. **DB設計 → ER図 → 画面遷移図** を先に確定してから実装
5. ワイヤーでUIを固め、スマホの見え方を最優先で調整
6. 実装 → テスト → デプロイ → 実機確認のループで改善

## 技術スタック（Whyを支える選択）

- Ruby / Ruby on Rails 7
- Hotwire（Turbo / Stimulus）
- Devise
- MySQL
- Render
- RSpec

※基本はRailsのSSR（サーバーでHTMLを生成して返す方式）で画面を構成し、  
体験向上が必要な箇所のみ Turbo（Frames/Streams）で部分更新しています。

---

## 非機能（最低限）

- HTTPS 強制
- Rails標準の CSRF / XSS 対策
- モバイル優先のレスポンシブ対応（PWAは未対応）

## ポートフォリオ用データ

固定のテストユーザー（`portfolio@example.com` / `Portfolio1234`）に、
サンプルデータを投入します。

```bash
bin/rails db:seed
```

データを初期状態に戻したい場合は以下を実行してください（対象は固定テストユーザーのみ）。

```bash
bin/rails portfolio:reset
```

本番環境で実行する場合は安全のため `ALLOW_PORTFOLIO_RESET=1` を付けてください。

```bash
ALLOW_PORTFOLIO_RESET=1 bin/rails portfolio:reset
```

## AI支援開発について（重要）

本プロジェクトでは、フロントエンド実装の一部に Codex を利用しています。
ただし、AIに無制限に任せるのではなく「任せる範囲」を先にルール化して運用しています。

以下は AI（Codex）への指示書であり、通常の開発作業では編集しないでください。

- `docs/codex-first-prompt.md`
  - Codex に最初に与える指示プロンプト（前提・禁止事項・進め方）
- `docs/frontend-brief.md`
  - Codex が参照するフロントエンド仕様（UI方針・実装ルール）

これらは アプリケーションの実行には関与せず、
AI支援開発を円滑に進めるためのドキュメントです。
